## 2. 最小知识与具体调用链（15～20 分钟）

```text
Document → chunk_documents() → list[Chunk]
          → retrieve_chunks(chunks, query, top_k) → list[RetrievalHit]
          → build_context(hits, max_chars) → ContextBundle(text, chunks)
```

例如命中 `Chunk("faq.txt", 0, 0, 8, "返品期限は30日")` 后，整理成两行：

```text
[1] faq.txt (0:8)
返品期限は30日
```

`[1]` 是本次上下文的资料编号，指向返回的 `chunks[0]`；它不是原文的 `chunk_index`。`(0:8)` 是原文切片范围，包含起点、不包含终点。今天只是把来源和原文排在一起，尚未生成回答，也没有验证模型是否正确引用。

只需补充两个字符串用法：

```python
pieces = ["甲", "乙"]
combined = "\n\n".join(pieces)  # "甲\n\n乙"，只在两项之间放分隔符
len(combined)                   # 4：两个文字 + 两个换行
```

字符串插值沿用已见过的 f-string，例如 `f"范围 {start}:{end}"`。`join` 类似 Java 的 `String.join`、Kotlin 的 `joinToString`；不过 Python `len(str)` 按 Unicode 码点计算，Java/Kotlin 的字符串长度按 UTF-16 代码单元计算，不能在 emoji 等场景当作完全相同。本日的上限按 Python `len()` 计算；**它不是字节数、token 数或模型费用上限**。

官方补充只看 [Python 3.11 的 str.join](https://docs.python.org/3.11/library/stdtypes.html#str.join) 和 [len](https://docs.python.org/3.11/library/functions.html#len) 的用途即可，不要求通读。今天不增加腾讯课程作业，不学 embedding、向量库、token 计数、模型请求、提示注入防御或回答引用校验。字符预算是本日简化的资料整理规则；后续真实模型请求还需考虑规则、问题和输出空间。

## 3. TODO 1：实现 `code/context.py` 的 `build_context()`（45～60 分钟）

目的：在指定字符上限内，保留完整证据块和可追溯出处。只改该函数；`ContextBundle` 已提供。

- 输入：`hits: list[RetrievalHit]`，已按检索结果顺序排列；`max_chars: int`。
- 输出：`ContextBundle`，其中 `text: str` 为完整排版后的资料，`chunks: list[Chunk]` 为实际纳入的原对象。
- 异常：即使 `hits=[]`，`max_chars <= 0` 也必须先抛 `ValueError("invalid_context_limit")`，消息精确一致。其余输入视为符合类型和上游片段契约，不需要另做类型校验。
- 不读写文件，无 CLI、退出码、网络或模型调用；异常由调用方处理。

按以下步骤处理：

1. 验证上限，为本次调用创建空的资料块列表和已纳入片段列表。
2. 按 `hits` 传入顺序逐项处理。从 `hit.chunk` 取得片段；不看 `score` 重新排序，不额外去重。
3. 编号从 1 开始，等于**已成功纳入的片段数量 + 1**。每块格式精确为 `f"[{编号}] {source_name} ({start}:{end})\n{text}"`。直接保留片段原文，不 `strip()`、不截断、不改写；头部不另放 `score` 或 `chunk_index`。
4. 多块之间用 `"\n\n"` 分隔，开头、结尾不额外添加换行。计算加入候选块后的**完整输出字符串**长度，包括头部、原文及块间换行；长度等于上限时允许纳入。
5. 放得下就纳入完整块，并将原 `Chunk` 对象放入返回列表；放不下就跳过该块，继续尝试后面的块。跳过不占编号，因此后面的编号连续。不要提前 `break`，也不要截断片段来塞入。
6. 返回整理结果。无命中或所有块都放不下时返回 `ContextBundle("", [])`。不修改传入的 `hits` 或其中对象；多次调用不共享结果列表。

完成标准：所有格式、完整长度边界、空结果、非法上限、原对象保留、顺序保留、连续调用独立性均符合契约；复制的 22 项旧行为仍通过。
